## Key Takeaways

- IAAA stands for Identity, Authentication, Authorization, and Accountability.
- Identity answers who the user is.
- Authentication verifies that the user is who they claim to be.
- Authorization decides what the user is allowed to access.
- Accountability ensures user actions can be logged, monitored, and reviewed.
- Broken Access Control can allow users to access unauthorized data or functionality.
- Authentication Failures can lead to account compromise.
- Logging and Alerting Failures can delay detection and incident response.
- Secure applications need both prevention and detection controls.
- OWASP Top 10 concepts are useful for developers, defenders, and security testers.

## Defensive Learning

- Server-side access control should always be enforced.
- Applications should follow least privilege principles.
- Strong authentication and MFA reduce account compromise risk.
- Login attempts and sensitive actions should be monitored.
- Logs should support investigation without exposing sensitive data.
- Security alerts should be created for suspicious behavior.
- SOC teams need good logging to investigate incidents properly.
- IAAA failures can affect real-world application security.
- Secure design, testing, monitoring, and review are all important.
