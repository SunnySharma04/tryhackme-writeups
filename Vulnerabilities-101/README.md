## Key Takeaways

- A vulnerability is a weakness that can create security risk.
- Vulnerabilities may exist in software, configurations, credentials, logic, or human behavior.
- CVSS helps measure vulnerability severity.
- VPR helps prioritize vulnerabilities based on real-world risk context.
- CVE identifiers help track publicly known vulnerabilities.
- Vulnerability databases are important resources for security research.
- Vulnerability research requires careful verification.
- A vulnerability is different from an exploit.
- Practical vulnerability learning should only happen in authorized environments.
- Vulnerability knowledge supports penetration testing, bug bounty, SOC analysis, and vulnerability management.

## Defensive Learning

- Defenders use vulnerability knowledge to reduce risk before attackers exploit weaknesses.
- Vulnerability scoring helps prioritize remediation.
- Organizations should regularly patch known vulnerabilities.
- Misconfigurations should be reviewed and fixed.
- Weak credentials should be removed or strengthened.
- Security teams should monitor exploit trends and threat intelligence.
- Vulnerability databases help defenders understand known risks.
- Responsible vulnerability research supports better security decisions.
- Vulnerability management is an ongoing process, not a one-time task.
