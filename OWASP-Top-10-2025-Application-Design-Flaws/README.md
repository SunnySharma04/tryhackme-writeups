## Key Takeaways

- Application design flaws can create serious security risks.
- Security misconfiguration happens when systems are deployed with unsafe settings.
- Default credentials, debug mode, exposed files, and weak permissions can create risk.
- Software supply chain failures can happen through vulnerable, outdated, or compromised dependencies.
- Dependencies should be verified, updated, and monitored.
- Cryptographic failures can expose sensitive data.
- Strong encryption, hashing, secure communication, and key management are important.
- Insecure design happens when security is missing from architecture, logic, or planning.
- Threat modelling helps identify risks early.
- Security should be part of the full software development lifecycle.

## Defensive Learning

- Secure configuration should be reviewed before deployment.
- Unnecessary services, debug modes, and exposed files should be removed.
- Dependencies should be checked for known vulnerabilities.
- Software supply chain security is important for modern applications.
- Sensitive data should be protected with proper cryptography.
- Keys and secrets should be managed securely.
- Applications should follow secure design principles.
- Threat modelling helps prevent security issues early.
- Developers, defenders, and security teams should work together to reduce application risk.
- Secure design helps prevent incidents before they happen.
